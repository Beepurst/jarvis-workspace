# Skills de production Webflow haut de gamme : plan d'implémentation

> **Pour les agents d'exécution :** sous-skill requis : superpowers:subagent-driven-development (recommandé) ou superpowers:executing-plans pour exécuter ce plan tâche par tâche. Les étapes utilisent la syntaxe de case à cocher (`- [ ]`).

**Objectif :** créer trois skills Claude Code (`webflow-fondations`, `webflow-sections`, `webflow-controle-qualite`) et prouver leur effet en reconstruisant l'accueil de la démo `demo-cuisine` sur une page `accueil-v2` notée 85/100 ou plus.

**Architecture :** trois skills en chaîne dans `.claude/skills/`, avec un fichier partagé de règles du connecteur. Le contrôle qualité s'appuie sur un script Node sans dépendance qui pilote Chrome sans interface via le protocole DevTools, prend les captures et mesure la page. Les points incertains du connecteur sont tranchés par des essais sur une page `labo` avant la rédaction des skills qui en dépendent.

**Technologies :** Markdown (skills), Node 26 (`node:test`, WebSocket natif), Google Chrome 155 sans interface, connecteur MCP Webflow 2.2.0.

**Spec :** `livrables/skills-webflow/2026-10-15-design.md`

## Contraintes globales

- Tout texte produit (skills, rapports, commits) est en français, sans tiret long (caractère U+2014).
- Aucune donnée de marché inventée. Aucune valeur de design présentée comme issue des templates si elle ne l'est pas.
- Accord explicite d'Edgar avant **chaque** publication (`publish_site`) et avant toute action destructrice (suppression d'élément, de composant, de variable, de police, de formulaire, compression d'images).
- Connecteur Webflow : `webflow_guide_tool` une seule fois par session, puis le même `session_id` et le même `agent_id` sur tous les appels.
- Site de test : `demo-cuisine`, id `6ad0991926a3286bbf229a23`. Page d'accueil actuelle : id `6ad0991c26a3286bbf22a32c`. **Elle n'est jamais modifiée.**
- Largeurs de contrôle : 1440, 991, 767, 478, 375 px. La référence mobile est 375 px (`context/import/brief-mobile-demo-cuisiniste.md`). Seuil de présentation : 85/100, sans bloquant.
- Les pages de démo portent la mention « Site de démonstration, entreprise fictive » (bandeau et pied de page) et une balise `noindex`.
- Les valeurs par défaut de l'échelle sont celles de la spec, section 4.
- Les classes de test sont préfixées `labo-` et ignorées par le contrôle qualité.

## Points de vigilance de la revue

1. **Texte français long à 375 px** (« Val-d'Oise », « Demander mon rendez-vous », titres plus longs qu'en anglais) : aucun débordement horizontal. Couvert par la fixture de la tâche 1 (mot long dans un bloc trop large) et par le critère bloquant de la tâche 10.
2. **Contenu resté invisible** quand une animation d'entrée ne se déclenche pas (bas de page, tablette) : la page reste lisible. Couvert par la mesure `invisibles` (tâche 1) et le critère bloquant de la grille (tâche 3).
3. **Images à un autre ratio que leur cadre** (photos Unsplash) : pas de déformation. Couvert par la mesure `imagesDeformees` (tâche 1).
4. **Menu burger** présent mais qui ne s'ouvre pas : détecté. Couvert par la mesure `burger` (tâche 1, cas `absent` sur la fixture, cas réel en tâche 10).
5. **Relance de `webflow-fondations` sur un site déjà équipé** (la collection Échelle existe depuis le labo) : aucun doublon. Couvert par l'étape d'idempotence de la tâche 8.

// Captures pleine page et mesures qualité d'une URL, à plusieurs largeurs.
// Usage : node captures.mjs <url> <dossier-sortie> [1440,991,767,478,375]
import { spawn } from 'node:child_process';
import { mkdirSync, writeFileSync, mkdtempSync, rmSync } from 'node:fs';
import { tmpdir } from 'node:os';
import { join } from 'node:path';

const CHROME = process.env.CHROME_BIN || '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome';
const [url, sortie, largeursArg] = process.argv.slice(2);
if (!url || !sortie) {
  console.error('Usage : node captures.mjs <url> <dossier-sortie> [1440,991,767,478,375]');
  process.exit(2);
}
const largeurs = (largeursArg || '1440,991,767,478,375').split(',').map(Number);
mkdirSync(sortie, { recursive: true });

const pause = ms => new Promise(r => setTimeout(r, ms));

function clientCdp(wsUrl) {
  const ws = new WebSocket(wsUrl);
  let id = 0;
  const attente = new Map();
  const ecouteurs = [];
  ws.onmessage = m => {
    const d = JSON.parse(m.data);
    if (d.id && attente.has(d.id)) {
      const { ok, ko } = attente.get(d.id);
      attente.delete(d.id);
      d.error ? ko(new Error(d.error.message)) : ok(d.result);
    } else if (d.method) {
      ecouteurs.forEach(f => f(d));
    }
  };
  return {
    pret: new Promise((ok, ko) => { ws.onopen = ok; ws.onerror = ko; }),
    envoyer: (method, params = {}) => new Promise((ok, ko) => {
      const i = ++id;
      attente.set(i, { ok, ko });
      ws.send(JSON.stringify({ id: i, method, params }));
    }),
    attendre: methode => new Promise(ok => ecouteurs.push(d => d.method === methode && ok(d))),
    fermer: () => ws.close(),
  };
}

// Code exécuté dans la page. Fait défiler pour déclencher les animations, puis mesure.

async function principal() {
  const port = 9300 + Math.floor(Math.random() * 500);
  const profil = mkdtempSync(join(tmpdir(), 'qa-chrome-'));
  const chrome = spawn(CHROME, ['--headless=new', `--remote-debugging-port=${port}`, `--user-data-dir=${profil}`,
    '--hide-scrollbars', '--no-first-run', '--no-default-browser-check', 'about:blank'], { stdio: 'ignore' });
  try {
    let wsUrl;
    for (let i = 0; i < 75 && !wsUrl; i++) {
      try {
        const liste = await (await fetch(`http://127.0.0.1:${port}/json/list`)).json();
        wsUrl = liste.find(t => t.type === 'page')?.webSocketDebuggerUrl;
      } catch {}
      if (!wsUrl) await pause(200);
    }
    if (!wsUrl) throw new Error('Chrome ne répond pas');
    const cdp = clientCdp(wsUrl);
    await cdp.pret;
    await cdp.envoyer('Page.enable');
    const resultat = { url, date: new Date().toISOString(), largeurs: {} };

    for (const largeur of largeurs) {
      await cdp.envoyer('Emulation.setDeviceMetricsOverride',
        { width: largeur, height: 900, deviceScaleFactor: 1, mobile: largeur < 768 });
      const charge = cdp.attendre('Page.loadEventFired');
      await cdp.envoyer('Page.navigate', { url });
      await Promise.race([charge, pause(30000)]);
      await pause(1000);
      const { result, exceptionDetails } = await cdp.envoyer('Runtime.evaluate',
        { expression: MESURE, awaitPromise: true, returnByValue: true });
      if (exceptionDetails) throw new Error('Mesure impossible : ' + exceptionDetails.text);
      resultat.largeurs[largeur] = result.value;

      const { cssContentSize } = await cdp.envoyer('Page.getLayoutMetrics');
      const hauteur = Math.min(Math.ceil(cssContentSize.height), 16000);
      const { data } = await cdp.envoyer('Page.captureScreenshot', { format: 'png', captureBeyondViewport: true,
        clip: { x: 0, y: 0, width: largeur, height: hauteur, scale: 1 } });
      writeFileSync(join(sortie, `capture-${largeur}.png`), Buffer.from(data, 'base64'));
      const m = result.value;
      console.log(`${largeur}px : débordement ${m.debordement.length}, police max ${m.taillePoliceMax}px, ` +
        `invisibles ${m.invisibles.length}, burger ${m.burger}`);
    }
    writeFileSync(join(sortie, 'mesures.json'), JSON.stringify(resultat, null, 2));
    cdp.fermer();
  } finally {
    chrome.kill();
    await pause(300);
    rmSync(profil, { recursive: true, force: true });
  }
}

principal().catch(e => { console.error(e.message); process.exit(1); });

const fichiersMd = d => readdirSync(d).flatMap(f => {

for (const nom of noms) {

grilles de cartes identiques s'enchaînent et que rien ne bouge. Cette skill fixe
des modèles de sections éprouvés et des règles qui empêchent ces travers, y
compris sur mobile.

1. Lis `.claude/skills/webflow-fondations/references/connecteur.md`.

| Pied de page | `references/sections/pied-de-page.md` | toujours, en fin |

## Règles anti-générique (toute la page)

1. **Rythme varié.** Chaque section prend `is-sm`, `is-lg`, ou aucune variante (padding moyen).
   Deux sections voisines n'ont jamais à la fois le même padding et le même fond.
2. **Une seule grille de cartes identiques par page**, au maximum.
3. **Au moins une composition asymétrique et un élément pleine largeur** par page.
4. **Accent rare** : la couleur `accent` apparaît au plus une fois par écran.
5. **Survol partout** : chaque lien et chaque bouton a un état `hover`.
6. **Titres serrés** : uniquement les classes `heading-style-*` des fondations.

## Règles responsive obligatoires

1. Chaque grille et chaque flex déclare son comportement à `medium`, `small` et
   `tiny`, même si c'est pour confirmer la valeur de base.
2. Images : `aspect-ratio` plus `object-fit: cover`, jamais de hauteur fixe en px.
3. Aucune largeur fixe ; utiliser `max-width` en rem ou en %.
4. Hero : hauteur minimale en `svh` (ex. `100svh`), jamais en `vh`.
5. Zones cliquables d'au moins 44 px de haut, boutons d'au moins 48 px, champs de formulaire en 16 px minimum (sinon iOS zoome à la saisie).
6. Boutons en pleine largeur à `tiny`.
7. Aucune taille de police en px dans une classe de section : uniquement les
   variables d'échelle via les classes des fondations.

4. Ajoute l'animation prévue par le modèle, selon `references/animations.md`.
5. Une section à la fois. Après chaque section, relis l'arbre
   (`data_element_tool > query_elements`) pour vérifier classes et textes.

## SEO de la page

- Un seul H1 (dans le hero). Les titres de section sont des H2, les sous-titres
  des H3. La balise et l'allure sont indépendantes : un H2 peut porter
  `heading-style-h1`.

- Page de démo : `<meta name="robots" content="noindex">` en code head de la page,

## Usage

Ouverture de page quand une photo forte porte la marque (réalisation, matière,
atelier). Contient le seul H1 de la page.

## Structure

```html
<section class="section hero_plein">
  <img class="hero_image" alt="...">
  <div class="hero_voile"></div>
  <div class="container hero_contenu">
    <div class="eyebrow">Cuisiniste à Cergy</div>
    <h1 class="heading-style-h1 hero_titre">...</h1>
    <p class="text-size-lg max-width-texte">...</p>
    <div class="hero_boutons">
      <a class="btn">...</a>
      <a class="btn is-on-dark">...</a>
    </div>
  </div>
</section>
```

## Composition (ordinateur)

- `hero_plein` : hauteur minimale `100svh`, flex colonne, contenu aligné en bas,
  couleur `sur-sombre`, overflow clip.
- `hero_image` : position absolue, `inset: 0`, largeur et hauteur 100 %,
  `object-fit: cover`.
- `hero_voile` : position absolue, `inset: 0`, dégradé du bas (70 % d'opacité de
  `texte`) vers le haut (transparent) ; garantit la lisibilité du titre.
- `hero_contenu` : position relative, z-index 1, padding bas `espace-xxl`.
- `hero_titre` : largeur max 14 em ; le titre tient en 2 ou 3 lignes.
- `hero_boutons` : flex, écart `espace-sm`, marge haute `espace-lg`.

## Responsive

| Point de rupture | Changement |
|---|---|
| medium (≤ 991) | `hero_titre` largeur max 12 em |
| small (≤ 767) | hauteur minimale `90svh` ; `hero_voile` plus couvrant (dégradé à 85 %) |
| tiny (≤ 479) | `hero_boutons` en colonne, boutons en pleine largeur ; `object-position` à ajuster si le sujet de la photo sort du cadre |

## Animation

`entree-hero` sur eyebrow, titre, texte puis boutons. `recul-image` sur `hero_image`.

## À éviter

- Titre centré au milieu de l'image : ancrer en bas à gauche.
- Plus de deux boutons.
- Hauteur en `vh` (saut de la barre d'adresse sur mobile).
- Photo sombre sans voile, ou voile uniforme qui éteint toute la photo.
```
