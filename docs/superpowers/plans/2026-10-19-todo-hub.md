# To-do du lendemain (Hub Agence) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remplacer la to-do Notion du hub par une to-do stockée dans Supabase, rangée en 6 thématiques, avec une page Aujourd'hui / Demain / Historique et un accès protégé pour que la commande `/demain` prépare le lendemain.

**Architecture:** Une table `taches` et une fonction SQL `appliquer_lot_taches` (transaction). Logique pure dans `src/lib/todo/` (jours en heure de Paris, retard, tri, validation), couche d'accès `src/lib/todo/db.ts`, routes de session `/api/todo/*` pour la page, routes hors session `/api/agent/todo` protégées par `TODO_AGENT_SECRET` pour la commande. La page réutilise les sous-onglets de la refonte.

**Tech Stack:** Next.js 15 (App Router), React 19, TypeScript, Supabase (`@supabase/supabase-js`, clé de service côté serveur), tests `node:test` lancés par `npm test`.

**Spec:** `docs/superpowers/specs/2026-10-19-todo-hub-design.md` (racine du workspace `/Users/ed/Desktop/jarvis-kleak`). Le code vit dans `livrables/hub-agence/`, **dépôt git indépendant** : tous les chemins de code ci-dessous sont relatifs à ce dossier, et les commits de code se font dans ce dépôt, jamais depuis la racine du workspace.

## Global Constraints

- Base de travail : créer la branche `todo-lendemain` à partir de `refonte-visuelle` (non fusionnée) dans `livrables/hub-agence/`.
- Ne pas toucher au worktree `livrables/hub-agence-ads/` (module Ads, en parallèle).
- Ne jamais lancer `npm run build` pendant qu'un serveur dev tourne.
- Le « jour » se calcule en heure de Paris (`Europe/Paris`), jamais en UTC. Format `YYYY-MM-DD`.
- Thématiques, dans cet ordre fixe : `prospection` « Prospection », `reunions` « Réunions », `production` « Production », `clients` « Clients », `admin` « Admin et finances », `outils` « Outils ».
- Qui agit : `edgar` ou `claude`, défaut `edgar`. Créée par : `edgar` ou `claude`.
- Style de la refonte : couleurs uniquement via les variables de `src/app/theme.css`, champs à 16 px sur iPhone, contrastes AA (les tests `test-couleurs`, `test-champs-ios`, `test-contraste` doivent rester verts).
- Aucune boîte de dialogue du navigateur (`alert`, `confirm`, `prompt`).
- Une ligne de la liste porte une tâche ; le détail se déplie ; le prompt n'est jamais affiché.
- Textes d'interface en français, sans tiret long.
- Secrets : jamais affichés dans la sortie d'une commande ni commités.

## Review Focus

1. **Minuit à Paris.** Une tâche ajoutée à 23 h 30 ou 0 h 30 heure de Paris tombe sur le bon jour ; aucun calcul ne passe par `toISOString().slice(0,10)`. Test : Task 1 (`jourParis`, `jourCibleRituel`).
2. **Repousser une tâche en retard de plusieurs jours.** Elle part au lendemain d'aujourd'hui, pas au lendemain de son jour d'origine, et son compteur augmente de 1. Test : Task 1 (`calculerReport`).
3. **Lot envoyé deux fois** (commande relancée après une coupure réseau). Il ne doit pas créer de doublons. Test : Task 4 (le lot porte un `idLot` obligatoire ; la fonction SQL refuse un `idLot` déjà appliqué, vérifié à la main en Task 4 step 6).
4. **Saisie invalide** (libellé vide ou fait d'espaces, thématique inconnue, heure `25:00`, date mal formée). Message d'erreur clair, rien d'écrit. Test : Task 1 (`parserTache`).
5. **Lot daté dans le passé ou visant des tâches déjà faites.** Refusé en entier. Test : Task 4 (`parserLot`) et fonction SQL.

  ```ts
  export type Thematique = "prospection" | "reunions" | "production" | "clients" | "admin" | "outils";
  export const THEMATIQUES: { cle: Thematique; libelle: string }[]; // ordre de la spec
  export type Acteur = "edgar" | "claude";
  export interface Tache {
    id: string; jour: string; thematique: Thematique; libelle: string; detail: string | null;
    acteur: Acteur; urgente: boolean; heure: string | null; // "HH:MM"
    faite: boolean; faite_le: string | null; creee_par: Acteur; reports: number;
    created_at: string;
  }
  export type TacheEntree = Pick<Tache, "thematique" | "libelle"> &
    Partial<Pick<Tache, "detail" | "acteur" | "urgente" | "heure">> & { jour: string };
  export type Resultat<T> = { ok: true; value: T } | { ok: false; error: string };
  export function jourParis(d: Date): string;
  export function jourSuivant(jour: string): string;
  export function jourCibleRituel(d: Date): string; // demain, sauf entre 0 h et 5 h (Paris) : aujourd'hui
  export function estEnRetard(t: Tache, aujourdhui: string): boolean; // jour < aujourdhui && !faite
  export function calculerReport(t: Tache, aujourdhui: string): { jour: string; reports: number };
  export function trierTaches(ts: Tache[]): Tache[]; // non faites d'abord ; puis urgentes ; puis heure (nulles en dernier) ; puis created_at
  export function grouperParThematique(ts: Tache[]): { thematique: Thematique; libelle: string; taches: Tache[] }[]; // ordre THEMATIQUES, groupes vides retirés, chaque groupe trié
  export function parserTache(brut: unknown): Resultat<TacheEntree>;
  export function parserModification(brut: unknown): Resultat<Partial<TacheEntree & { faite: boolean }>>;
  ```

- [ ] **Step 2 : Écrire `supabase/todo.sql`** (idempotent, même style que `supabase/crm-phase-1.sql`)

Table `taches` : `id uuid pk default gen_random_uuid()`, `jour date not null`, `thematique text not null check (in les 6 clés)`, `libelle text not null check (length(trim(libelle)) > 0)`, `detail text`, `acteur text not null default 'edgar' check (in ('edgar','claude'))`, `urgente boolean not null default false`, `heure time`, `faite boolean not null default false`, `faite_le timestamptz`, `creee_par text not null default 'edgar' check (in ('edgar','claude'))`, `reports int not null default 0`, `lot_id uuid`, `created_at`, `updated_at timestamptz not null default now()`. Index sur `jour`. Table `taches_lots (id uuid primary key, applique_le timestamptz not null default now())`. RLS activée sans policy sur les deux.

Fonction `appliquer_lot_taches(lot jsonb) returns jsonb`, `language plpgsql` (une fonction = une transaction) :

```sql
-- lot = { idLot, jour, aujourdhui, creations: [TacheEntree...], reports: [uuid...], suppressions: [uuid...] }
-- 1. insert into taches_lots(id) values (idLot) : une violation de clé = lot déjà appliqué -> raise exception 'lot_deja_applique'
-- 2. reports : update taches set jour = (lot->>'jour')::date, reports = reports + 1, updated_at = now()
--    where id = any(...) and faite = false ; si le nombre de lignes touchées != nombre d'ids -> raise exception 'report_invalide'
-- 3. suppressions : delete where id = any(...) ; même contrôle du nombre -> 'suppression_invalide'
-- 4. creations : insert avec creee_par = 'claude', lot_id = idLot, jour = (lot->>'jour')::date
-- retourne { creees, repoussees, supprimees }
```
